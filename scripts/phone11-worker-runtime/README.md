# Bound worker-only source candidate

This inert factory builds the actual maintained chat notification/media, recording analysis/retention/capture and ESL starter graph. It does not listen, start workers on import, provide a CLI, inspect Docker, or establish that the old owner stopped. It is not installed or production-qualified.

Run from the repository root:

```sh
node scripts/phone11-worker-runtime/build.mjs
node --test scripts/phone11-worker-runtime/test_lifecycle.cjs scripts/phone11-worker-runtime/test_bound.cjs
PHONE11_WORKER_PG_BIN=/path/to/existing/postgresql-17/bin python3 scripts/phone11-worker-runtime/test_schema_migration.py -v
```

The Python suite also supports existing PostgreSQL16 tools and explicitly skips when unavailable; it creates a private Unix-socket-only cluster and removes it after confirmed stop. It does not use Docker, production databases or providers. Source pins refuse changes to the real maintained graph. Attestation functions are extracted verbatim from the retained runtime into this build; their SQL is not forked. The same owned pool is leased and checked before deferred imports/startup. Its application name remains `phone11_retained_runtime`, matching that exact attestation.

An operator-owned launcher may require the generated `.cache/phone11-worker-runtime/worker-bound.cjs`, call `prepareBoundWorkerRuntime(privateBinding)`, then explicitly await `runtime.start()`. It must retain the controller, own process liveness/signals, and await `runtime.close()` on failure/shutdown. There is deliberately no ambient credential loader or default launcher. Private input is copied before asynchronous setup; it must not be logged. Five enabled booleans and capture mode (`off`, `cleanup-only`, `enabled`) are explicit. This is six actor dispositions, not permission to enable them all. Disabled actors require no provider keys and construct no capture instance. Preserve the authorized old actor policy; `cleanup-only` can still stop/upload native recordings and requires its own deliberate disposition. Profile-photo cleanup uses its existing external-owner flag and is not added to this worker graph.

`start()` is an operator action only after ingress is fenced/moved, old restart disabled, in-flight/native/external work reconciled, and the exact old actor is positively absent. The factory cannot prove this. Do not start a second worker as a preview. Known startup failure unwinds started actors; close fences maintained schedulers and awaits active ticks before owned Redis/pool closure. A 30-second drain timeout or stopper failure reports `unconfirmed` and retains the pool; late completion does not silently change that result. The caller must reconcile rather than force-kill or restart another owner. Existing unref'ed worker timers mean a launcher must supply process liveness when ESL is disabled.

Redis is limited to the websocket graph's `pbx:events` publication and tracks in-flight operations for closure. Concurrent first publications share one connection. A settled failed connection is cleared so a later new event can reconnect. Each admitted publication has finite connection/command limits, no offline queue, and no automatic message retry. Failed events are not replayed. This intentionally replaces the old unbounded reconnect/queued-command behavior; real Redis/network recovery remains unqualified. It does not add caching, rate-limit or other Redis consumers.

The historical captured worker map contains20 relations and two capture sequence-USAGE rights; it is not automatically the maintained graph's complete grant constructor. The accompanying W handoff records exact conditional DND SELECT additions and cloud-column deltas. `assertWorkerSchema` refuses missing actor-required columns/privileges; its current-column SELECT check also covers analysis-only configuration conservatively. The exact analysis `claimJob/validateJob/finishJob` SQL uses explicit columns and does not require retention's `speaker_identity` UPDATE. The gate is a minimum compatibility check, not complete ACL/RLS/trigger/default/role containment proof.

`cloud-columns-additive.sql` is a separate source-only prerequisite derived from the existing maintained migration: add only nullable `capture_stop_requested_at TIMESTAMPTZ` and `speaker_identity JSONB`, with no default/backfill. Existing columns must match exactly; the bounded transaction refuses incompatible definitions atomically. It neither grants privileges nor executes during runtime preparation. Do not reapply the full cloud migration. No migration or grant has been applied by this work.

Qualification still requires an isolated captured-schema PG16 run with the exact final worker bundle, actual external pg/ioredis/vendor graph, exact role/column/sequence grants and negative cases, and safe synthetic/no-provider actor dispositions. The bundle exceeds the existing262144-byte child-input cap: stage exact raw artifact bytes through a reviewed exclusive private file/chunk path, hash and hold it before load. Do not increase a shared helper limit or send base64 in the existing request. Source/unit/PG17 schema checks are not actual actor/provider/PG16 runtime acceptance.

Takeover/rollback must retain the old container definition/credentials and reconcile each actor's durable state, described in `H/worker-runtime-next-v1/ACTOR-STATE.md`. The actual deployed57e80 SIGTERM ignores the dispatcher stopper, does not await worker stop or close PG/Redis, and its ESL socket-close path can reconnect. It has no proven finite natural exit. Maintained source fixes do not update that running process. This is a concrete operational stop/drain blocker, not an absent new wrapper. Never bring the old owner back while new-owner state is unknown. This candidate does not retire/revoke the elevated login, change global recording policy, or qualify providers, phones or Android. Trial60 remains unchanged.
