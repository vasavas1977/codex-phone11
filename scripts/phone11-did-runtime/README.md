# Bound DID-only receiver

Source candidate for the existing qualified routing factory; not installed or started against production. Import/constructor perform no PG/HTTP work. There is no global bootstrap, signal hook, worker, credential loader or default CLI. The only exported runtime operation is `createDidRoutingListener(privateBinding)` returning explicit `start()` and idempotent terminal `close()`.

Build and focused local checks from the repository root:

```sh
node scripts/phone11-did-runtime/build.mjs
node --test scripts/phone11-did-runtime/test_listener.cjs
PHONE11_DID_PG_BIN=/path/to/existing/postgresql-17/bin python3 scripts/phone11-did-runtime/test_acl.py -v
```

The PG suite supports existing16/17 tools and skips explicitly if unavailable; it uses a new private Unix-socket-only cluster, no Docker/TCP, and confirms stop before removing its owned root. It qualifies this ACL query against a reconstructed catalog projection, not the restored production schema. A missing filename in the initial test-only Node loader caused SIGABRT before cases; the loader now sets its exact synthetic filename. The corrected initial three-case run passes and the owned cluster is removed.

An operator launcher provides explicit IP host/port, strict `database` binding (host/port/database/user/password/verified CA), independently obtained role/database OIDs and expected client/server addresses/port, and a separate private64-lowercase-hex `integrationSecret`. Input is copied before effects. The secret must differ from the DB password; actual private caller/receiver equality and separate custody remain deployment obligations. No FS/dotenv/default secret is consulted. The proposed container port is3032 with an operator-configured loopback host publication; this module does not publish ports or prove network isolation. Tests bind only disposable local loopback ports.

Call `await listener.start()` only after source/config/role/HBA/runtime custody and the actual native caller are qualified. Retain the returned controller and `await listener.close()` in the launcher's error/signal path; signals are deliberately not installed by this library. Start is one-shot per bundled module graph. No application source claims ingress cutover authority.

The bound pool is exactly the maintained strict JS-pg/TLS pool. The existing retained `requiredAuthority` and `attestOwnedPool` functions, including SQL, are extracted verbatim for this build. That leased pool's role/session/OIDs/flags/TLS/addresses/settings/no-membership/ownership/DDL authority is checked before listener creation; the application name remains `phone11_retained_runtime` to match the reused contract. The read scope additionally requires exactly the qualified8 public relations/columns, ordinary/RLSoff/no rewrite targets, no other public column SELECT, DML/REFERENCES/table/sequence rights, and no executable public security-definer routine. It does not grant, migrate or claim a blanket system-catalog/temporary-object lockdown. Public ACL/schema/role drift refuses startup.

The routing factory's three source modules are pinned to the exact575d factory already qualified in isolated PG16. Routes admitted here are only POST `/api/kamailio/route`, GET `/health` and `/api/health`. Auth/register/full API/CDR/upload are404 before body parsing/SQL; the real header-secret middleware remains intact. JSON is bounded4KiB with fixed parser errors. Health reports startup qualification, not a continuous current-pool/role attestation. Query exceptions are replaced by a fixed code before the actual factory's existing error logger; no raw PG/private input error is returned or logged by this wrapper.

Pending native listen uses AbortSignal, preventing late bind after close. Close synchronously fences new HTTP and query admission, then awaits actual setup settlement, HTTP closure and all already-admitted underlying query promises before ending PG. This includes a disconnected client whose async handler is still awaiting SQL; a later query from that handler is refused. No forced process stop/connection kill or replacement occurs. Each startup/cleanup phase has an explicit bounded budget up to30s; timeout or failed close remains cleanup-unconfirmed and retains resources rather than ending a pool still in use or retrying setup. Caller must preserve/reconcile that state. Shutdown may return a routing failure to a request already disconnecting; read-only SQL has no job/provider side effects.

Nine actual-loopback listener tests use injected external PG only; four owned PG17 ACL cases exercise exact SQL acceptance and extra SELECT/DML/sequence/missing-column/RLS/definer refusals. These are not new actual-image/PG16 receiver acceptance. Existing factory PG16 success and maintained same-pool attestation evidence remain distinct from this executable's future isolated qualification. Deployment still needs exact source/vendor image, UID1001, readonly private config/CA, role/OIDs/network/3032 availability, HBA, actual same-pool/native readiness, restart policy and a separate reviewed native caller transition/rollback. No current route or service changed. No provider/SIP/customer call, old login retirement, device acceptance or coldboot is claimed. Trial60; Android/phones deferred.

V2 additionally includes views/materialized views/foreign tables in the effective table-right census. A DELETE-only grant on an unrelated updatable public view (directly or via PUBLIC) now refuses the same read-only scope. Four actual PG17 ACL cases pass; the nine listener cases are unchanged and were not redundantly rerun. V1 preparation/source snapshots remain in history/v1; no production use occurred.
