# Retained HTTP library — source only

This began as the maintained integration of reviewed operational bound-v2 artifact `82ddacbb272d4989bcf9ab602a54d96d31571a2902d9b1c8936e83170264d8e9`. `PROVENANCE.json` preserves that historical artifact and its original source hashes; it is not acceptance of the later attestation change. `composition.ts` remains its exact copy. The current `bound.ts` adds same-pool prelisten attestation; `SOURCE-PINS.json` deliberately pins that change and the separately accepted `ac9d454` integration-auth extraction among35 inputs. The build emits no committed runtime artifact and never listens or starts workers.

From the repository root:

```sh
node scripts/phone11-retained-runtime/build.mjs
node --test scripts/phone11-retained-runtime/test_bound.cjs
```

The artifact and build manifest are written under ignored `.cache/phone11-retained-runtime/`. A source-input change requires deliberate pin/review updates; the builder does not silently bless new inputs. No runtime configuration, secret, live database, provider or recording file is read by the build. The16 focused tests use synthetic input, inert external PG/BetterAuth transports and loopback HTTP. They execute the actual maintained binding, query/release/refusal and lifecycle code, but simulate PostgreSQL result rows. They do not prove actual SQL, authentication, TLS or storage acceptance.

`createBoundRetainedRuntime(privateBinding)` validates explicit production HTTPS auth values, discrete verified-TLS database binding and absolute recording/chat roots. It refuses conflicting existing auth/storage settings and excluded mailer configuration. It binds `configureOwnedPbxPool` before any getter and before dynamic storage/router evaluation. Auth `/me`, the media SDK, playback and transactions use the same maintained `getPhone11Auth`/`getPool` graph; arbitrary unrelated auth/pool injection is not public. Setup is single-attempt and terminal on failure. Private environment drift/closure causes503 before admitted handlers. Before returning any app, setup now leases a client from that same configured pool and runs one bounded, parameterized SELECT. Required `databaseAuthority` input supplies explicit role OID, database OID, client IP, server IP and server port; no production defaults or guessed values exist. Its plain own data fields are validated, copied and frozen before the first await. Names come from the strict database binding. The SELECT requires exact current/session role and OIDs, LOGIN, verified connection TLS, expected addresses, read-committed isolation, fixed search path/application/timeouts, no unsafe role flags or membership/ownership, and no database/public-schema CREATE. False, NULL, absent, extra or ambiguous result rows refuse. A successful lease is released; a failed/timed-out/refused lease is discarded in finally. Connection, query and release errors use the existing sanitized terminal setup refusal and pool close; failed end remains unconfirmed cleanup. It returns no pool, lease, authority values or row details. Close uses the same terminal owned-pool promise; maintained HTTP shutdown drains before calling it.

Only canonical session/me/readiness/signout, six wake actions, chat-media upload/read and recording playback are admitted. Full tRPC/admin, sign-in/reset/mobile-config, native CDR, FS/Kam callbacks, recording/voicemail ingestion, voicemail retrieval, profile/photo, websocket and background workers are excluded. `/api/auth/get-session` remains404, matching both maintained and captured legacy HTTP gates; programmatic BetterAuth getSession remains internal. Caller/owner/tenant/cookie/replay/expiry/file predicates are unchanged. There is no CLI/serve/start API, listener, migration or provider startup. Importing remains inert; explicit setup now connects only to its supplied strict database binding. Its client connection timeout is5s and startup query deadline is10s, with the existing server statement/lock/idle bounds. The app is unavailable until attestation succeeds.

Before any real listener, separately qualify actual restricted role/ACL/schema/TLS identity, current consumer/ingress selection, storage inode/mount/UID authority, real installed auth behavior and exact permitted SQL. Media workspace FOR SHARE still needs a deliberately qualified narrow lock-column contract; no broad business UPDATE, sequences, DDL, ownership, RLS bypass or production grants follow. Prior clone-only assigned-authority proof used UPDATE(id) on user_extensions/extensions/tenants and UPDATE(created_at) on tenant_memberships; it does not grant that direct-write capability in production. Wake has service-owned lock/write/provider requirements, and actual pilot/SIP/capture/provider flags remain unqualified.

The same-graph pool ownership seam does not prove every resource is drained. Actual wake offers may create APNS sessions and late cancellation work; disconnected async work is not settled merely because HTTP closes. The local source graph has no Redis import or configured Redis auth storage, but external runtime/resource behavior still needs exact-image qualification. The new attestation is a source-level identity/settings and selected escalation guard, not an exact object/column/sequence/function privilege matrix, RLS/schema-readiness proof, all-pool-connections guarantee or real PostgreSQL result. Other pool connections are still constrained by the same strict config; role/ACL drift after startup is not continuously attested. It does not attest storage custody or listener admission. Existing PG16 receipts for82dd apply to that prior artifact, not this successor. This library does not retire old3000, change its login, fence duplicate workers, prove reboot recovery or establish provider/device acceptance. Trial60 and Android/phone deferrals remain.
