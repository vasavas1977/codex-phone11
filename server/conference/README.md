# Provisioned PBX audio conference controls

The old mobile conference implementation fabricated active rooms, participants and local success after transport failure. The replacement uses authenticated tRPC, fresh tenant and room authorization, durable operation claims, and observed FreeSWITCH room/member state. The mobile migration removes legacy ESL secrets and synthetic history.

Default capability is unavailable. `PHONE11_CONFERENCE_CONTROLS_ENABLED=true` is an explicit deployment setting, not approval to enable it. The implementation has not been deployed or tested with live calls. Activation requires review/application of `migration.sql`, tenant-isolated existing room mappings (`p11_t<TENANT>_<NAME>`), current workspace memberships, and an authenticated reachable ESL service. The migration is never run at startup. Room owners/current workspace administrators can moderate; explicitly enrolled users can view. No global application-admin bypass exists.

The supported adapter reads live inventory and controls mute/unmute/kick/lock/unlock/end of provisioned rooms. `canManage` is calculated server-side. Dial, room creation, join, recording and role changes remain unavailable. Empty bridge numbers never imply a dialable destination. `joinConference` in the legacy store only refreshes a room view; leaving that view no longer kicks all callers.

Durable claims are written before external effects. Identical successful requests return the stored snapshot. Pending/uncertain operations block replay; operators must reconcile actual provider state before clearing claims. A timeout is never permission to redial. Retried client requests must preserve their idempotency key. There is intentionally no automatic pending-claim expiry. The server sanitizes transport/protocol errors before returning them to clients.

`media_mode='video-mcu'` records possible provisioned topology only and does not enable video. The user's selected conferencing direction is Connect11 LiveKit with an interpreter; this adapter is limited to existing PBX audio controls. LiveKit requires verified project/service configuration, server-minted tenant-scoped room grants, identity/role mapping, mobile/web SDK audio/video lifecycle, interpreter participant routing/permissions, consent, reconnect behavior and real multi-device acceptance before video availability can be asserted. No SFU track or participant is synthesized.

Provider wire schema was checked against SignalWire's upstream `conference_jlist` implementation: https://github.com/signalwire/freeswitch/blob/master/src/mod/applications/mod_conference/mod_conference.c . Control command reference: https://developer.signalwire.com/freeswitch/applications/conferencing/ . Tests use protocol-shaped fixtures; deployed provider/version parity remains a rollout check.
