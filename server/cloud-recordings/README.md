# Cloud recording candidate

This source is an inactive candidate. No migration, recording capture, provider request, or live rollout is performed by importing the router. `migration.sql` requires a separately reviewed migration. Capture defaults off and additionally requires `PHONE11_CLOUD_RECORDING_CAPTURE_ENABLED=true`, a workspace policy, authenticated routing metadata and an operational capture adapter.

Policies are off/manual/automatic. Only a current active tenant owner/admin can edit; global user role is insufficient. Off stops future capture and invalidates analysis leases. Pending/active capture tokens remain available for verified recorder-stop and physical spool cleanup before failure finalization. Existing owned media and completed summaries remain readable until their original retention expiry. Lowering policy retention applies to new records. A purge worker must delete the private file before completing its purge lease; expired metadata remains as a tombstone so legacy playback cannot reopen access.

The authenticated FS outbound dialplan binds only exact `sip_auth_username`/realm and channel Unique-ID. Incoming authenticated wake offers persist SIP Call-ID, binding, tenant and extension before transient wake cleanup. An authenticated ESL channel can bind only an exact, unique recent SIP Call-ID to that immutable record. Rewritten or ambiguous leg IDs remain unsupported until a trusted explicit bridge mapping is commissioned. Caller numbers and timestamps are never ownership keys. Existing CDR bodies cannot supply an extension or overwrite the cloud media storage path.

The mobile API returns only records belonging to currently assigned active extensions. Media uses the existing authenticated playback endpoint with additional cloud retention checks. Analysis accepts server-owned media only: `claimJob`, `validateJob`, and `finishJob` fence each attempt with an opaque five-minute lease, current policy and tenant/extension checks. Failed attempts retry at most three times. `claimPurge` and `completePurge` provide the physical-deletion worker contract.

`storage_key` currently denotes private server-disk storage, not an S3 durability claim. No vendor spend or provider configuration is established by these source changes. Real two-leg audio capture, announcement completion, interrupted-upload recovery, exact inbound/outbound mapping, Gemini processing, retention deletion and handset playback remain required commissioning tests.
