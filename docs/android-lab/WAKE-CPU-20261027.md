# Android incoming setup CPU ownership — 27 October 2026

The staging wake candidate now retains CPU ownership across the FCM callback,
foreground-service handoff, HTTP claim and SIP setup. Previously this interval
had no application-owned partial wake lock; foreground FCM receipt alone did
not establish screen-off incoming-call reliability.

Each validated delivery acquires a separate opaque handoff. The coordinator
adopts it only when call UUID, binding UUID, expiry and native epoch match.
Duplicate or rejected deliveries release their own handoff without releasing
or extending the accepted call's lease. Connection, cancellation, setup failure,
revoke and attributable service destruction release the accepted ownership.
The setup lock does not remain held for active-call audio.

The deadline is the remaining delivery lifetime, capped at 30 seconds. An
independent timer releases ownership even when the Android main looper stalls;
the framework timeout remains a second safeguard, not an OS hard deadline.
Unattributable destruction before `onStartCommand` relies on the bounded timer.
Scheduling delays remain possible; this is not a real-time guarantee. Pending
handoffs are capped at eight and released leases cancel queued timers.

`WAKE_LOCK` is declared in the wake-only manifest. Normal builds and the
foreground-only native candidate retain their existing profile restrictions.
The staging candidate retains the pinned Siprix trial limit of 60 seconds.

The new strict APK verifier mode checks staging package identity, service
export/permission boundaries, wake permissions, matching Firebase resources,
Hermes, pinned ARM libraries and an independently supplied signer fingerprint.
Source profile flags and an origin string in DEX do not prove effective runtime
configuration. The exact source/prebuild/build receipts must accompany the APK.

The CPU lifecycle regression runs in the Android CI contract lane. Build and
verification results belong to the artifact receipt, not this source design
record. Physical screen-off/Doze incoming calls, audio routes and OEM power
management remain unaccepted until tested on the Samsung A55. No production
backend, provider configuration or iOS binary is changed by this source work.
