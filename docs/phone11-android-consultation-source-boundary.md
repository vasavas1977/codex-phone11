# Android consultation source candidate

This candidate adds two-leg consultation and one attended REFER attempt under the existing Android foreground Siprix process lease. Ordinary builds and the existing foreground trial keep consultation disabled. No background, wake, video, direct/blind transfer, provider policy, audio quality, or device acceptance is established.

The separate Gradle property `phone11AndroidConsultationSourceEnabled=true` requires `phone11AndroidForegroundSourceEnabled=true`; both default to false. The existing isolated trial package and manifest gates remain mandatory. JavaScript additionally requires `EXPO_PUBLIC_PHONE11_ANDROID_CONSULTATION_SOURCE=1`, exact SDK/build/trial capabilities, `consultationSourceCandidate: true`, and all five consultation bridge methods. Legacy foreground capability reports remain compatible while consultation is off. `transfer` remains false. No app config, plugin, workflow, provider, grant, credential, or license is activated by this change.

Independent source review found that the initial Android validator omitted the shared/iOS leading `+`. The corrected grammar accepts one optional leading `+` followed by 1–32 digits, `*` or `#`; the plus is excluded from that 32-character count. Embedded/double/bare plus and 33 dial characters reject before hold or attempt reservation.

The native owner keeps the original call dictionary, account, generation, history identity and one consultation request throughout the attempt. SDK IDs cannot be reused within a generation. Parent relationship events precede the second leg. Local hold command acceptance plus a matching held callback precede shared-engine authorization to dial; the current SDK hold state is checked again before dialing. The consultation starts muted. Mixer command acceptance, a matching switch callback and current hold states precede unmuting and `ready`. Original mute controls keep the focused consultation muted consistently; manual hold and DTMF are rejected during consultation.

Cancel ends only the owned consultation and waits for its termination before removing the original's local hold. Remote hold is preserved. Restoration requires a fresh matching original switch callback after termination and confirmed local hold removal. The pinned SDK's `-1047` (`ECallAlreadySwitched`) is accepted only as an idempotent focus confirmation in that restoration window; it never substitutes for the callback. All other focus failures remain failures. Callback ordering that never provides that fresh confirmation produces `return_failed`, not invented audio readiness.

Hold, continuation, invite, focus and termination waits have bounded timers. A REFER timeout retains the in-flight fence: it does not emit a fabricated SDK outcome, allow another REFER, or permit a guessed return. A late matching SDK outcome may update native state; the shared engine's timed-out promise stays timed out. A successful SDK transfer callback reports `completed` and leaves termination to the SDK. Explicit End preserves the shared engine's retained-original/remaining-leg contract. Cleanup failures quarantine the runtime with both records retained until successful destruction; stale generation callbacks and timers cannot affect a replacement owner. An unsolicited SDK redirect's exact unowned related leg is rejected and retired, and the runtime is quarantined; an ambiguous/reused ID is never used to end a known owned leg.

The pinned AAR is SDK 1.1.0, build `20260905_1222`, SHA-256 `3173ee8bae7aa37d3be3b44f7533d43b4e4d8625110d1d2bd8d79367973c9198`. Its actual Android APIs include `callTransferAttended(int,int)`, `callHold(int)`, `callGetHoldState(int,IdOutArg)`, `mixerSwitchToCall(int)` and callbacks `onCallTransferred(int,int)`, `onCallHeld(int,HoldState)`, `onCallSwitched(int)`. Transfer callbacks have no request ID, so the native attempt cannot be retried. [Siprix API documentation](https://docs.siprix-voip.com/rst/api.html) describes asynchronous hold and transfer outcomes, status zero for successful transfer, automatic mixer switching on termination, and `ECallAlreadySwitched=-1047`.

Validation uses injected state/callback mocks and the exact cached AAR, Android 35 and React Native 0.81.5 declarations with `javac -Xlint:all -Werror` in OFF/OFF, ON/OFF and ON/ON gate combinations, plus shared-engine/media/ownership regressions and TypeScript. These checks execute no SDK, capture no media, and contact no provider. Independent source review is required before integration; actual attended transfer, restoration ordering, cancellation, microphone privacy, server REFER semantics and two-phone audio remain separate acceptance work.
