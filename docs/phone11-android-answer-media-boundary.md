# Android Answer media boundary

Source candidate based on `c5e29bf2ef1f041390eede367b3b60de65ff5296`. The combined review at `9f28cad` reproduced Android Answer reaching the SDK while a provider-moved meeting still had pending or failed teardown. Its incoming observer waited for media cleanup, but the explicit Answer action did not wait for that observer.

The default-off Android foreground trial now shares one tracked incoming preparation between its observer and explicit Answer. The preparation captures the exact authenticated owner object, provisioned account object, native call ID, history/start lifetime and local generation. Answer waits for the existing meeting drain and acknowledged native audio stop, then checks that the same ringing lifetime still holds the coordinator's exact active SIP lease before marking the native command started. Permission denial preserves a previously prepared ringing lease; teardown failure refuses Answer and permits a later explicit retry for the same valid ring. Retired or unmounted preparation releases only its own late-acquired lease. A connected original or retained consultation keeps the existing SIP lease until SDK termination; consultation creates no second lease or OS call.

The iOS CallKit path, ordinary platform selection, meeting implementation, SDK gates and Android native runtime remain unchanged. Tests exercise the actual provider, meeting lifecycle and media coordinator against SDK mocks, including public `moved`, late camera publication, audio-stop acknowledgement/failure, auth/account/call replacement, reused IDs, unmount, duplicate Answer, callback-first connection and refusal to take another SIP lease. These checks establish source behavior only; actual permissions, device audio, SDK/provider calls and attended transfer remain separate acceptance.
