# Phone11 person photos (24 September 2026)

Zoom Workplace treats a signed-in profile picture as part of a person's
identity across mobile profile, chat, contacts, and meetings. Its help pages
also describe initials/no-photo fallback and note that meeting hosts can hide
participant profile pictures. References:

- https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0063582
- https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0060639
- https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0065840

Phone11's design rule is to put a 34–48 px photo next to an identifiable person
row and a larger photo on a focused caller/profile view. Active video remains
the person's image; a video tile's name badge does not need a second avatar.
Message text, @mention tokens, workspace/channel labels, and action labels are
not person rows. Without a verified photo, show initials; never guess a photo
from a display name or number suffix.

The signed-in workspace profile and server-authorized Team directory use
`ProfileAvatar`, which validates tenant ID, user ID, and a versioned relative
photo URL before fetching with the session token and no persistent image cache.
Local address-book contacts use only their device URI, with no upload. A call
number must uniquely match an exact Team extension in the current SIP tenant
or a normalized, unique local phone number. Ambiguous matches show initials.

Surfaces covered by this change: Recents rows and actions, active/incoming
calls, the current-call banner, recording detail, Team Chat mentions,
conversation members, read-receipt readers, the channel meeting invitee picker,
and the in-room participant list. Existing chat message rows, inboxes, Team
Contacts, local Contacts, and profile views already use these sources.
Incoming calls and the call banner use only an already-loaded, owner-and-tenant
scoped Team directory; neither starts a network or address-book read while a
call is ringing. If the roster is not loaded, initials are intentional.
In-room participant photos require the server-admitted local LiveKit identity,
an exact same-tenant participant identity, and an authorized Team directory
member. Unknown/guest identities show initials.

The PBX admin membership screen includes inactive members but its response
does not carry an authorized photo descriptor, so it retains initials until
that endpoint has an explicit tenant-safe photo contract. Meeting video tiles
show real media; an audio-only grid/tile view needs a separate layout change
before it can display a photo. Source tests and signed builds cannot establish
that every photo renders on both iPhones; test the same account/tenant on
devices and confirm photo removal, account switch, and poor-network fallback.
