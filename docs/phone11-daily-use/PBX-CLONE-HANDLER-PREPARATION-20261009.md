# Clone handler preparation: explicit pg connection seam

This source stage adds `scripts/phone11-pbx-clone/real-pg-adapter.ts`. It prepares a real `pg.Pool` connection seam for the isolated Node+PG clone design, without importing application routers, discovering targets or running a driver/handler rehearsal. The source candidate is `cd2b317c01d27ee472dca969a097133bd8968464`. Product database adapters, initializer, workflows and package locks are not changed by this component.

`createRealPgAdapter` currently refuses with `EXECUTION_UNBOUND` before reading environment names, inspecting runtime identity or constructing a pool. Its execution-admission pin is explicitly null because Linux Node/software, worker image, observed restricted LOGIN and compatible rollback admission are not available. A future reviewed revision must bind genuine observed custody/software/role evidence and verify the corresponding private input; filling in well-shaped hashes is not admission. No owner permission or invented signature is substituted for this missing technical evidence.

The pure `admitCloneConnectionInput` accepts at most 8192 UTF-8 bytes of private JSON/memory input. Every object has an exact key set. It requires a distinct cluster identifier, pinned source and nonempty artifact references, private/no-network/no-mount custody assertions and a uniquely named synthetic non-owner restricted LOGIN (`p11_clone_runtime_<32-hex-attempt>`). The generated password is 64 lowercase hex characters and is never accepted from a URI, ambient configuration or defaults. The returned single-use token exposes no fields or credentials. Validation checks shape and fixed values; it does not authenticate receipt contents, check files/socket ownership or prove role grants. Those remain the outer clone custodian's responsibility.

The target is fixed to `/run/phone11-pbx-clone/socket`, `phone11ai`, port 5432, inside the same private container as PostgreSQL. The real factory is async and lazily imports pg only after admission/environment/runtime checks, because pg's entry consults NODE_PG_FORCE_NATIVE. The offline suite refuses any runtime pg import. The real factory requires Linux/x64 and the exact admitted Node 22 version. It rejects inherited PG*, POSTGRES*, DATABASE*, DB_*, NODE_PG_*, NODE_OPTIONS and NODE_PATH keys without consuming their values. It supplies explicit host/database/user/password/SSL and startup settings, so pg cannot use a missing password or target as a pgpass/environment fallback. The outer worker still starts with a clean environment; this module never overrides HOME or reads configuration/credential files. No production principal is inferred from a role name.

The created object provides `getPool().query/connect`, `query`, `withTransaction` and `close`; it is an explicit factory instance, not a global singleton. The future entry/resource module must bind these three database exports only after admission. Clients expose promise-based `query(text, values)` and idempotent `release`; callback/query-config/native methods are unsupported. The import audit must verify the selected actual handler graph uses this subset before loading it. SQL text, parameter arrays, results and pg/handler errors are forwarded inside worker memory without SQL extraction or result mocks. Transactions use the same leased client for BEGIN, callback, COMMIT or ROLLBACK. Failed rollback destroys the client without replacing the original error. An unsettled callback query refuses rather than committing.

Limits are fixed: pool maximum 2, connection 2s, query 5s, transaction/lease 15s, whole adapter 60s, shutdown 3s; server statement/lock/idle-transaction limits are 3s/1s/5s. Cancellation/deadline closes the adapter, destroys leases, fences late results/commits and waits for pending connection cleanup within the shutdown bound. `close().ended` means driver pool shutdown only, not verified container removal or database rollback. A commit racing cancellation is ambiguous; the outer runner must retain evidence and reconcile, without automatic retry. Unknown cleanup returns a fixed failure. The outer orchestrator must independently bound execution and verify exactly owned container cleanup and recovery rehash.

There are no console/log side effects. `safeCloneError` returns only a fixed adapter, allowlisted SQLSTATE/TRPC code or UNCLASSIFIED. Raw errors remain in memory for handlers; printing them, fulfilled result rows or credentials is forbidden. The future top-level runner still must enforce the 64KiB fixed output contract. JavaScript memory is not claimed to be securely erased.

`createCloneAdapterForTests` accepts an injected transport only when NODE_ENV=test. Production entry/bundle review must exclude calling or exposing it. Focused tests are pure/injected offline evidence, not pg connection, SCRAM, catalog, actual handler, HTTP authentication, Redis or production proof. They cover target/admission/env substitution, credential/refusal/privacy, transaction error identity, deadlines, late acquisition, rollback/release/cancellation and uncertain shutdown. No real pg pool or SQL is executed here. The next source step is the separately owned entry/import audit and genuine runtime/image/admission preparation; existing restore/full-inspector/synthetic readiness successes remain separate evidence.
