# 3000 worker handoff operator boundary

`scripts/phone11-worker3000-handoff.py` is a source-only, read-only pin verifier. It accepts a root-owned mode-0600 JSON manifest beneath root-owned non-writable parents. It reads Docker inspect and the old live bundle hash without printing the container environment. It never stops or starts a service, writes database rows, replays notifications, changes routing, or interacts with Connect11 rooms.

The manifest has schema `phone11-worker3000-handoff/v1`, `old` (`container_id`, `image`, `bundle_sha256`), `release` (`image`, `bundle_sha256`), and `snapshot_sha256`. The snapshot digest is SHA-256 of canonical JSON containing the old container's complete `Config`, `HostConfig`, `Mounts`, and sorted network names, as produced by `snapshot()`. Its complete values must be captured privately from the exact live container; they include secrets. The release must be a reviewed bundle-only overlay whose labels identify the old image and new bundle. The operator checks the overlay's inherited image process configuration against the old image. Passing prints `PINS_VERIFIED_ONLY`, never a handoff authorization.

The present old 3000 bundle claims pending notifications as `attempted` before sending. It has no awaited dispatcher drain. Its shutdown also interrupts auth, wake, PBX and recording routes, and the loaded Kamailio config has no maintenance gate for new SIP calls. These are operational boundaries, not fields that an operator can safely accept as caller-supplied booleans. Thus there is no `--execute`, `--stop`, `--start`, or rollback mutation mode in this candidate.

A later, separately reviewed mutation operator needs operation-specific machine evidence before the first stop: an active ingress maintenance gate with a live route readback and admitted-request drain; a SIP admission gate and existing call/wake/recording drain tied to the current Kamailio and FreeSWITCH instances; a held database pending-row barrier with its session alive until the old worker exits; and a bounded observation/disposition of already `attempted` notifications. It must recheck old ID/image/bundle/config and the new image immediately before stop, then stop that exact old ID, observe it exited, and only then create one new default-role 3000 container with inherited environment, mounts, network, host limits and port. It must verify the new running bundle hash and health before releasing maintenance. It must retain pending rows and never reset `attempted` to `pending`.

If new 3000 fails, rollback must first stop and observe the new default worker exited, then restart the pinned old image/config. If DND was exposed, rollback must disable `PHONE11_CHAT_NOTIFICATIONS_ENABLED` in the restored old worker until the DND state is reconciled; simply restarting the old container with its previous `1` environment is ineligible. `verify_exclusive_phase()` supplies source-level assertions for worker ordering, configuration preservation, and that notification restriction. It is not a live receipt generator. Existing `provider_fence_uncommissioned` is not bypassed by this operator, and Connect11 room zero is not a condition of this 3000 handoff.
