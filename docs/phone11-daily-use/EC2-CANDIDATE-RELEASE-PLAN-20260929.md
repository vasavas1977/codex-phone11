## Pre-route acceptance and guarded switch

Before a route change, review migration-order and ledger state read-only against the actual `cp11-postgres` / `phone11ai` target; use read-only schema preflights (`scripts/phone11-plain-video-admission-preflight.ts`, `scripts/phone11-pbx-schema-preflight.ts`) and reviewed migration receipts if any change is required. The approved one-copy protected restore already passed; repeating that restore needs a concrete new mismatch or other reason. Confirm selected-tenant membership, extension mapping, Connect11 customer/scope metadata, grant profile, and provider admission without printing tokens or issuing a join token merely to obtain a green health check. The prior status-only HTTP 200 and schema comparison do not cover authenticated isolation.

The operator restricts probes to an exact GET query allowlist, excluding explicit mutation and join-token routes. This is **not a guarantee of database read-only execution**: `phone.getConfig` invokes the legacy provisioning schema initializer, which issues `CREATE`/`ALTER` statements on its first request. Review that behavior and the target schema before running protected probes; the source-only test suite does not execute those server handlers or authorize their database effects. The fixed five-query smoke fixture also does not replace the separate directory, meeting-invitation, or role-boundary acceptance checks below.

Start only the distinct workerless candidate after image/runtime review, without changing Nginx. Require its direct loopback `/api/health` to identify the exact build and `runtimeRole: api-candidate`, and verify the running bundle/image. Run protected authenticated probes against the candidate for existing phone and chat, a mixed tRPC batch, selected-tenant `pbx.directory.list`, channel and direct meeting admission/invite read paths, normal-user admin denial, cross-tenant and revoked-member denial, and previously working mobile join behavior. Record redacted results and correlation IDs, never credentials or response tokens. Recheck 3000/3004, worker ownership, and direct wake throughout.

The new route operator must acquire the Phone11 route lock; compare the full Nginx site/dump and predecessor/candidate pins at prepare **and immediately before activation**; seal root-only before/after site bytes and a receipt; and show a diff containing exactly the two tRPC `proxy_pass` targets. The [old route operator](../../scripts/phone11-chat-inbox-release-route.py#L274) demonstrates these prepare/activate/rollback states for an earlier topology, not an executable 3016 switch. Keep both candidates running until outstanding requests drain.

Rollback is a guarded proxy-only restoration to the **freshly revalidated** healthy 3016 image/container. Require the exact sealed active site, current Nginx generation and unchanged 3016 predecessor before restoring the receipt's original site; syntax-check, reload, and repeat public, 3000, 3004, and wake probes. If site, predecessor, or a dedicated route drifts, stop and require operator review rather than overwriting concurrent changes. Retain additive schema on application rollback. If a new schema or feature activation makes 3016 incompatible, do not advertise it as a rollback target until compatibility or a separately reviewed fallback is proven.
