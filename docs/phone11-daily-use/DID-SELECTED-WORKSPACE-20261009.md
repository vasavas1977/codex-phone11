# DID destinations in a selected workspace

The admin DID editor admits multiple active memberships only after fresh workspace admission and the separate literal `explicitDidRouteDirectories: true` capability. `explicitTenantReads` continues to cover tenant.get/members only; implicit dashboard statistics remain limited to one membership. Legacy APIs without the new capability retain editing for a freshly matched single membership and refuse multi-workspace editing.

The capability covers selected extensions, IVR menus, ring groups, queues, business hours and DID assignment. It reports endpoint semantics, not schema availability: the existing per-facility booleans still decide which destination types exist. Each destination list receives the selected tenant. Server reads require active owner/admin authority, and assignment retains the actor/tenant authorization lock, tenant-bound active destination lock and tenant-bound DID update.

DID queries opt into fresh mount reads, no retained inactive cache and cancellation on unmount. Fetching/error destination rows are hidden and cannot authorize saving. The editor binds account/workspace/membership admission and read-observation revisions; replaced reads retire the editor. Missing/inactive destinations and removed inventory rows cannot be submitted. Pending completions after scope replacement or unmount cannot close, refetch or publish an error into a replacement editor. Existing workspace admission cancels/removes prior PBX/IVR queries and unmounts forms during admission refresh or account/tenant changes.

Focused offline component tests use injected query results/events; they do not claim browser or real QueryClient transport acceptance. Existing actual-router authority tests check SQL scope and held authorization/destination guards with mocked transports; optional PostgreSQL fixtures execute only under their established dedicated test-database contract. Source checks and CI do not prove deployment, carrier activation, real principal access, provider routing or physical calls.
