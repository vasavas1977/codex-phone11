# Profile photo REST route: source-ready operator, not commissioned

`scripts/phone11-profile-photo-route.py` is a separate, default-off route
operator for the **VoIP host's** Nginx site. The outer TLS edge remains
unchanged. The operator inserts three case-insensitive path selectors and
sends only these methods to the pinned API candidate:

| Request | Candidate |
| --- | --- |
| `POST /api/profile/photo` | upload |
| `GET /api/profile/photo/:tenantId/:userId` | read |
| `DELETE /api/profile/photo/:tenantId` | remove |

Other methods on these paths continue to the port-3000 baseline. All `/api/trpc`
locations, the active candidate marker, authentication routes, SIP/call routes,
meetings, and other paths stay byte-for-byte in the original site body. The
script shares `/run/phone11-parallel-api.lock` with the existing candidate
operator, requires exact current site/Nginx dump/executable hashes, pins the
candidate Docker ID/image/build/port, checks its health and unauthenticated
photo rejection, and verifies the Nginx worker generation and response status
after reload. It writes a protected before image, intent, and activation
record. Rollback verifies baseline health. If the process stops before writing
the activation record, the intent and exact staged bytes allow a bounded,
idempotent restore. A changed Nginx master after a host reboot additionally
requires the exact active route in the running config and pinned candidate
container/image. If recovery fails after writing the original site, it
reinstalls and verifies the exact staged photo route. If neither serving
generation can be proved, it reports `recovery_ambiguous` for operator
investigation. A rollback interrupted after writing the original site but
before Nginx reload is also recoverable: retry reloads the exact original
bytes, waits for old workers, and verifies baseline health. Foreign site bytes
or candidate identity stop recovery.

Activation additionally requires a root-owned mode-0600, canonical JSON
preflight document no older than five minutes. Its schema is
`phone11-profile-photo-preflight/v1`. The document must bind the same candidate
container ID, image, build and port, and positively establish four facts:
photo tables are **absent**; the private media path is persistent and owned by
the API runtime; photo deletion/orphan cleanup is running on exactly one
appropriate worker and tolerates absent tables; the candidate rejects
unauthenticated photo requests. These booleans are an operator attestation,
**not** evidence generated by this script. A reviewed preflight producer and
operator evidence are required before live activation.

The operator also reads the existing protected candidate probe bundle. It
requires the root-owned mode-0600 file and its exact SHA-256, takes only the
`existing_phone` read-only authentication headers in memory, and requests the
currently routed `profile.photoCapability` for the pinned test tenant through
local Nginx. It must return `available: false` before and after route
activation. Credentials are never printed or written to the route evidence.

The app uses tRPC batching. Routing only
`/api/trpc/profile.photoCapability` cannot safely switch its capability: a
batch may include other procedures. Keep the existing `/api/trpc` candidate
route intact. The narrow live sequence for the **current** candidate, which
already contains the photo REST code and reports photos unavailable while the
tables are absent, is:

1. Establish the private media mount and start one reviewed cleanup worker
   that safely loops while photo tables are absent.
2. Produce fresh schema-absent, storage, worker, and authentication evidence.
   Activate this photo-only route to the pinned current candidate. Confirm
   local Nginx returns its candidate marker and authenticated 401 response for
   all three photo methods, while other routes and the tRPC capability remain
   unchanged and healthy.
3. Confirm the same 401 photo response and candidate marker through the **outer
   public HTTPS edge**, using a request without credentials. This proves the
   outer edge forwards the new path; local port-80 probes alone do not.
4. Apply the additive photo tables **last**. With REST and cleanup already
   serving, the current candidate can then report `available: true`.
   Separately verify authenticated upload, versioned read, removal, tenant
   isolation, cleanup, and avatar propagation on two devices. This operator
   does not execute the migration or claim those post-schema checks.

Future candidate builds that include `PHONE11_PROFILE_PHOTO_COMMISSIONED`
require an explicit separate rollout plan for that gate. Its default-off state
does not satisfy step 4 without a subsequent validated enablement.

The operator does not override the separate
`provider_fence_uncommissioned` guard for baseline replacement and must never
be used to replace the baseline or infer Connect11 session safety. The current
source-only tests exercise method selection, existing-route preservation,
candidate/preflight rejection, marked 502 failures, slow Nginx worker drain,
activation, rollback, and interruption recovery including config/reload/probe
failures. Production `nginx -t`, public
HTTPS proof, worker-generation proof, authenticated tenant tests, and two-device
avatar propagation remain live acceptance gates.
