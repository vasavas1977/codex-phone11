# Build 15 handset checkpoint — 11 September 2026

The paired-device inventory again reported Phone11 1.0.0/build 15. These observations extend the [release checkpoint](RELEASE-CHECKPOINT.md); they do not establish production calling readiness.

## Foreground outgoing echo

- The Phone tab showed **Ready to call** without opening Diagnostics or manually registering.
- The app dialed the internal test extension `*9196`. FreeSWITCH observed an **ACTIVE** channel running its `echo` application, created at 03:11:03 UTC.
- The session later ceased to exist. Phone11 showed **Call ended**, Close returned to the ready dialpad, and Recents contained one outgoing `*9196` entry with displayed duration **1:09**.
- The user has not yet confirmed audible echo or pressing End. This is signaling, UI and saved-history evidence; the terminal cause, actual audio quality and handset-initiated termination remain unverified.
- The subsequent FreeSWITCH file-log check recorded approximately 69.98 seconds and `NORMAL_CLEARING`. That terminal reason does not distinguish a manual End press from an SDK-triggered end.

## Direct incoming echo

- A test used the same internal server route as the earlier build 13 check, explicit `To: sip:3001@sip.phone11.ai`, PCMA and a 45-second automatic cleanup guard. It bypassed the public-number carrier.
- The script required zero active server channels and a fresh extension 3001 registration before calling. The test ran from 03:15:45 UTC and ended with **NO_ANSWER**. No test session remained active.
- Captured signaling contained INVITE, the proxy's 100 response, CANCEL, a cancellation acknowledgment and 487. It contained no handset ringing response or successful INVITE answer.
- The INVITE targeted the current saved handset contact, approximately 85 seconds after its last registration. The earlier public-DID To-header hypothesis does not explain this explicitly normalized direct test.
- iPhone Mirroring disconnected with **iPhone in Use** during testing and subsequently required Mac authentication. Continuous physical foreground app state was not established. Mobile NAT expiry and iOS suspension must be distinguished before changing routing or credentials.
- The contact later expired without renewal. Server NAT-ping filtering excluded this contact, but the pinned SDK documents a default 30-second client keepalive; the bridge's unset keepalive option is not evidence that client keepalives are disabled. No handset packets appeared in the bounded signaling capture. [Siprix reference](https://docs.siprix-voip.com/rst/api.html), [Kamailio NAT settings](https://www.kamailio.org/docs/modules/5.8.x/modules/nathelper.html).

## Next acceptance gate

Use Phone11 directly on the physical iPhone with its Phone tab visible and the screen on; use the Mac for test coordination. First establish immediate incoming receipt and real audio/End behavior, then repeat after a controlled idle interval while the app remains foregrounded. Keep this separate from public-carrier incoming and locked/background acceptance. Native push registration remains disabled in build 15.

Raw packet captures, device inventories and server output are kept in private evidence storage, outside the public repository. No credentials, contact routing addresses or media keys are included here.
