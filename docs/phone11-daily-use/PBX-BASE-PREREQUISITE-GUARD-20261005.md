# PBX base prerequisite source boundary — 5 October 2026

The [read-only preflight](../../scripts/phone11-pbx-schema-preflight.ts) previously reported `ready_for_migration` for a NOT NULL `extensions.tenant_id` with DEFAULT 1 and no tenant foreign key. The standalone [advanced migration](../../server/pbx/advanced-routing-migration.sql) also accepted a nullable DEFAULT 1 base without that FK and created routing tables. A new reproduction of the original `f4dd06b` SQL in a fresh disposable local PostgreSQL database confirms the latter behavior; it does not change any historical rehearsal receipt.

Both paths now require int4 base IDs and single-column primary keys, a NOT NULL int4 tenant column without a default, identity or generated expression, and exactly one validated, nondeferrable, same-schema `extensions.tenant_id → tenants.id` FK with NO ACTION update/delete behavior. All four internal RI triggers must have the matching PostgreSQL function, relation and event and be enabled for origin sessions (`O` or `A`); replica sessions and replica-only/disabled triggers fail closed. Missing or ambiguous preflight catalog results fail closed. Existing ordinary/persistent/non-inherited relation checks remain required.

Preflight observes one repeatable-read, read-only catalog snapshot and rolls back. It neither reserves a later migration nor proves writer deployment, existing data cleanliness after privileged bypasses, or commissioning readiness. Advanced SQL repeats the same catalog predicate after locking and rechecking both exact base relations, before its first DDL. A prerequisite failure returns SQLSTATE `55000` and performs no base repair or advanced DDL. A concurrent base mutation must commit before the guard can acquire its lock and is then checked in the migration's read-committed transaction; existing lock timeouts still refuse without DDL. Valid bases and migration replay preserve the existing FK identity.

The [local writer harness](../../scripts/phone11-pbx-local-writer-rehearsal.ts) now expects unsafe ordering to be refused and verifies the unsafe base remains unchanged. No prerequisite is automatically applied. The [ordinary prerequisite](../../server/pbx/extension-tenant-prerequisites.sql) and [explicit legacy DEFAULT 1 upgrade](../../server/pbx/extension-tenant-legacy-default-prerequisites.sql) remain separately reviewed operator actions.

Focused validation uses only a newly initialized task-owned PostgreSQL 17 cluster and injected catalog clients: unsafe default/nullability, absent/wrong-schema/wrong-column/unvalidated/deferrable/cascading/duplicate FKs, disabled/replica-only RI triggers, missing primary key, replica session, valid ALWAYS-enabled triggers/replay, and concurrent default mutation. Existing migration target, relation, routing and lock-timeout regressions are retained. This is local source evidence; the protected-clone writer/rollback rehearsal has not been run here.

Changed advanced SQL, preflight and harness bytes invalidate future source-file pins and source-commit bindings in [rehearsal readiness plans](../../scripts/phone11-pbx-rehearsal-readiness.ts). Future plans require new hashes, a new exact source commit and fresh operator/reviewer approval. In particular, the old advanced SQL SHA `e5675dfe34bfdd2ce76a12dc1c6b4d848edd36e34908962deb39c0d8f470ee96` belongs to the old source and old receipt. Never relabel it as evidence for this guard. The legacy prerequisite SHA `2deb0b79fa7d00aea093ba7c00099a99f8df7a756700c001579c94439207bed8` remains unchanged.

Production commissioning still requires authoritative current writer/principal and rollback-artifact inventories, reviewed access profiles, an independently preserved protected clone and complete per-artifact rehearsal evidence. This change grants no database, deployment, provider or release authority.
