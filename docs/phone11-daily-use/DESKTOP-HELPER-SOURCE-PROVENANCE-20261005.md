# Desktop helper source receipt boundary — 5 October 2026

Local trial packaging now requires helper provenance receipts in addition to the existing byte-integrity manifest. A fresh manifest around historical helper bytes no longer satisfies the package gate. Both producers require receipts for the exact committed packaging HEAD; even a later app-only commit requires a new receipt. Retained Build 116 artifacts and their original source pins remain unchanged.

For Windows, supply an absolute `PHONE11_WINDOWS_HELPER_RECEIPT` alongside `PHONE11_WINDOWS_HELPER_EXE`. The validator consumes the existing `integrity-receipt.json` emitted by the trusted manual desktop-helper workflow: source/Siprix revision, helper hash/size/architecture, bootstrap test source/result, native C++/CMake, SDK header, import library and both runtime DLL hashes. The checked-out SDK must remain pinned and clean. PR helper checks intentionally do not retain this artifact; a green PR run alone is insufficient input. Existing DLL pins and PE checks remain in force.

For macOS, supply absolute `PHONE11_MAC_NATIVE_RECEIPT` and `PHONE11_MAC_INPUT_RECEIPT` paths. These consume the established local `native-provenance.json` and linked `input-before.json` format, not a CI attestation or newly invented generator. Both must bind the exact HEAD, C++/CMake/package-lock bytes, input-receipt hash, helper hash/size, config, full staged manifest, retained framework inventory and consumed SDK header/framework files/relative links. The retained SDK input view must remain available. The committed bootstrap source is checked; this Mac contract records no helper launch and proves no bootstrap execution. It preserves the existing limited framework provenance without claiming a complete vendor SDK checkout.

The package entry points check provenance before building/copying, verify staged/copied helper bytes against the same receipt snapshot, and repeat source/receipt/SDK checks before reporting success. Windows performs its final provenance and committed-source checks after all awaited packaged-integrity, archive and executable checks, immediately before printing the success path. Its staged and packaged gates also require the copied directory to contain exactly the regular helper and two runtime DLL files with the frozen receipt hashes; extra, missing, symlinked or changed copied inputs are refused. Generic helper-only checks remain available without that copied-directory argument. Each receipt gate ends with a synchronous receipt/input/inventory recheck and then a synchronous exact HEAD/native-clean check, after its last await. Persistent replacements during an awaited check are rejected before the gate returns. Missing, stale, incomplete or changed inputs fail closed. Native/app source must remain committed; untracked or ignored native inputs are rejected. Older unreceipted stages cannot be packaged through these commands. No automatic fallback, receipt rewriting or old-package retagging is provided. Failed output must not be treated as an accepted package.

These are consistency checks on operator-supplied files. They cannot authenticate receipt custody, prove compiler causality, provide an atomic filesystem snapshot against another process, defeat a writer that changes and restores inputs between checks, or replace independent producer/package review. The final pass blocks local JavaScript callback interleaving, but its reads are sequential: an external writer can still change an already read file during that pass or after return. Inputs and receipts must remain under exclusive operator custody throughout packaging. The source gate does not cover toolchain authenticity or all compiler/system-library inputs. macOS remains an ad-hoc signed arm64 trial app; Windows remains an unsigned x64 trial directory. No build, signing, upload, provider configuration, licence activation or device action was performed for this change.

Validation uses actual validators with isolated Git/filesystem fixtures for current/stale receipts, consumed-input mismatches, replacement helpers, relative links and changes during packaging. The unchanged integrity-only verifier accepts reminted manifests around replacement helpers; the new source gates reject them. The original retained Mac two-receipt contract was also checked read-only against its original `b5a97e6bdf41c66347547dfb8340f954d8318bce` checkout, without modifying or relabeling its artifacts.
