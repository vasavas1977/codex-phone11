This folder contains an opt-in source prototype against the public FreeSWITCH v1.10.12 module, not a patch derived from the deployed module and not a replay service. No native process, route, configuration, spool entry or customer content was read or changed. No full FreeSWITCH source tree/image was fetched or built.

## Prototype contract

New optional `error-completed-dir` selects a separately preprovisioned absolute private directory. When unset, all old module behavior is unchanged. When set, the HTTP-failure branch uses the new publisher and does not fall back to rewriting the legacy spool. The deployment must prove the new directory is a fresh completed-only namespace, with no alias to legacy error/success log directories, no unrelated writer, no symlink ancestors/nested mount override, and exact held host/native custody. This prototype does not supply that installer or claim the parameter alone proves those facts.

The native helper accepts a held directory FD owned by its effective UID with exact mode0700. It creates a random pending leaf with O_EXCL/O_NOFOLLOW and mode0600, checks regular/single-link ownership and size, loops over short writes and finite EINTR interruptions, checks file fsync, then checks close without an unsafe retry. Only afterward does it publish the original UUID `.cdr.xml` name using a single no-replace rename. A successful directory fsync is required before returning COMPLETE. The payload is passed unchanged; no parse, retagging, URL re-encoding or `cdr=` addition occurs in the producer.

Existing final or pending entries, symlinks and collisions are never overwritten or removed. All created pending/final records survive every failure branch. Close/rename ambiguity and directory-fsync failure after publication return UNCERTAIN. A failed directory fsync can leave a complete visible final record; it is preserved, never relabeled as durable producer success or destructively retried. A crash before publication leaves a pending record; after rename it can leave a final record with uncertain directory durability. No created file is unlinked by the helper, and no original legacy file is opened.

A caller cannot persist new bytes if opening/creating/writing the storage itself fails; this prototype makes no loss-free hardware, ENOSPC or power-failure guarantee. Fsync remains synchronous and can stall reporting. Actual reporting latency, disk backpressure and target-filesystem crash durability need qualification before any use. A root-controlled actor can still mutate files; the future directory/source custody boundary must exclude other authorized writers. This is not a generic untrusted-root defense.

The no-replace implementation uses Linux renameat2(RENAME_NOREPLACE) without a replacement fallback. Local tests use Darwin renameatx_np(RENAME_EXCL). The Linux syscall adapter, Linux feature macros/headers, full FreeSWITCH module compilation/ABI and Windows behavior are not qualified. Unsupported publication returns refusal, not a destructive fallback. Default legacy paths retain their existing behavior and remain ineligible for automatic completion claims.

## What passed locally

Ten focused native C-helper tests compile with `cc -std=c99 -Wall -Wextra -Werror` and use only owned synthetic directories: full/short/EINTR writes; partial/zero write; file fsync; file close; rename; directory fsync after publication; existing final/pending preservation; final/pending symlinks and hard-link collision; unsafe parent mode; process exit after file fsync and after rename. They verify retained exact bytes,0600/single-link new files and no overwritten original. The source derivation hash and opt-in branch are checked. Patch dry-run against the pinned single upstream file passed. These tests do not compile or execute the full switch/module, run a Linux image, simulate a machine power loss or establish a deployed producer identity.

Command: `python3 -m unittest discover -s . -p test_publication.py -v`.

## Exact build boundary and remaining acceptance

The maintained `infra/docker/freeswitch/Dockerfile` installs unversioned vendor apt packages and does not bind its unused FREESWITCH_VERSION argument to a source build. It is not evidence that this reference source equals the loaded module. Before constructing a native release, obtain the exact mapped mod_xml_cdr module path/ELF hash/build-id, installed binary/source package versions and vendor patch source, matching FreeSWITCH development ABI/configuration/dependency versions, and a reproducible image/build recipe. Keep the current immutable image and all private configuration/mounts as rollback authority. A version string or matching output format is insufficient.

Then derive the patch against that exact source, build a new immutable image without replacing unrelated native code, independently review it, and qualify isolated HTTP failure publication/crash/collision/concurrency on the target filesystem/image. Admission must bind a fresh completed-only directory and the newly loaded producer generation; old spool files and orphan pending records remain retain-only. Future replay additionally needs current3030 runtime/auth/admission and durable snapshot/journal/ACK bindings. None is activated by this prototype. Trial60 and deferred phones/Android/provider acceptance are unchanged.
